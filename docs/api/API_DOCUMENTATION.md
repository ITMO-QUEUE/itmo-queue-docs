# Документация ITMO Queue API

Система электронной очереди для защиты лабораторных работ. Архитектура сочетает **REST API** (управление данными и действиями), **SSE** (динамическое обновление списков очередей в реальном времени) и **WebSockets** (персональный обмен местами между студентами).

---

## 1. Авторизация и матрица ролей

Авторизация основана на серверных сессиях. При успешном входе (`POST /auth/login`) сервер устанавливает `HttpOnly` cookie `sessionId`, которая автоматически прикрепляется ко всем последующим HTTP, SSE и WebSocket запросам.

### Роли в системе
* **`Admin`** — полный доступ ко всем эндпоинтам и действиям в системе.
* **`Teacher`** — создание и настройка очередей, управление статусами студентов, выставление оценок.
* **`Student`** — просмотр очередей, запись, выход, перенос в конец, обмен местами и просмотр своей истории.

---

## 2. REST API эндпоинты

### Авторизация и профиль
| Метод | Путь | Роли | Описание |
| :--- | :--- | :--- | :--- |
| `POST` | `/auth/login` | Все (Public) | Вход по 6-значному табельному номеру (`^[0-9]{6}$`) и паролю. Создаёт сессию. |
| `POST` | `/auth/register` | `Admin` | Регистрация нового пользователя (`Student`, `Teacher` или `Admin`). |
| `POST` | `/auth/logout` | Все авторизованные | Завершение текущей сессии (`204 No Content`). |
| `GET` | `/me` | Все авторизованные | Получение профиля текущего пользователя (`UserProfile`). |

### Очереди и история
| Метод | Путь | Роли | Описание |
| :--- | :--- | :--- | :--- |
| `GET` | `/queues` | Все авторизованные | Получение списка всех существующих очередей. |
| `POST` | `/queues` | `Teacher`, `Admin` | Создание новой очереди с указанием работ, приоритетов и лимитов. |
| `PATCH` | `/queues/{queueId}` | `Teacher`, `Admin` | Изменение параметров или статуса очереди (`Preregistration`, `Active`, `Paused`, `Completed`). |
| `GET` | `/me/queues` | `Student`, `Admin` | Список очередей, в которых участвует текущий студент. |
| `GET` | `/students/{studentId}/queues` | `Admin` | Список очередей конкретного студента. |
| `GET` | `/me/history` | `Student`, `Admin` | История сдач текущего студента (фильтры: `date`, `discipline`, `work`). |
| `GET` | `/students/{studentId}/history` | `Admin` | История сдач конкретного студента. |

### Действия в очереди
| Метод | Путь | Роли | Описание |
| :--- | :--- | :--- | :--- |
| `POST` | `/queues/{queueId}/entries` | `Student`, `Admin` | Запись в очередь с передачей списка работ и ссылок на артефакты. |
| `DELETE` | `/queues/{queueId}/entries/me` | `Student`, `Admin` | Выход из очереди (недоступно в статусе `Defending`). |
| `POST` | `/queues/{queueId}/entries/me/move-to-end` | `Student`, `Admin` | Одноразовый перенос себя в конец очереди (`moveUsedAt == null` и `queueNumber > 3`). |
| `POST` | `/queues/{queueId}/entries/me/switch/{queueNumber}` | `Student`, `Admin` | REST-резерв для создания заявки на обмен местами (`queueNumber >= 3`). |
| `PATCH` | `/queues/{queueId}/students/{studentId}` | `Teacher`, `Admin` | Смена статуса участника (`Waiting`, `Called`, `Defending`). |
| `POST` | `/queues/{queueId}/students/{studentId}/evaluate` | `Teacher`, `Admin` | Выставление баллов (`Accepted`) или фиксация неявки (`Absent`). |

## 3. Динамическое обновление очередей (SSE)

Для отображения актуального состояния очереди без перезагрузки страницы клиент подписывается на поток Server-Sent Events:

* **Эндпоинт:** `GET /queues/{queueId}/stream`
* **Заголовок ответа:** `Content-Type: text/event-stream`

### Типы событий SSE
1. **`queue.updated`** — срабатывает при записи нового студента, выходе, переносе в конец или успешном обмене местами. Передаёт актуальный массив `students` с пересчитанными `queueNumber`.
2. **`participant.status_changed`** — срабатывает, когда преподаватель вызывает студента (`Called`) или начинает защиту (`Defending`).
3. **`queue.status_changed`** — срабатывает при постановке очереди на паузу (`Paused`), возобновлении (`Active`) или закрытии регистрации.

## 4. Обмен местами в очереди (WebSockets)

Обмен местами работает через персональный двусторонний канал `WS /ws/me` (авторизация по куке `sessionId`).

### Бизнес-правила обмена
1. Позиция инициатора в очереди должна быть **не ниже 3 включительно** (`fromQueueNumber >= 3`).
2. Позиция целевого студента должна быть **не ниже 3 включительно** (`toQueueNumber >= 3`) и не совпадать с позицией инициатора.
3. Оба студента должны находиться в статусе `Waiting` (не вызваны и не защищаются).
4. Заявка имеет ограниченный срок жизни (TTL, например, 30–60 секунд), после чего автоматически переходит в статус `Expired`.

### Примеры сообщений WebSocket

**1. Предложение обмена (`Клиент А -> Сервер`):**
```json
{
  "type": "switch.propose",
  "queueId": 42,
  "targetQueueNumber": 5
}
```

**2. Входящее уведомление (`Сервер -> Клиент Б`):**
```json
{
  "type": "switch.incoming",
  "request": {
    "id": 108,
    "queueId": 42,
    "fromStudentId": 15,
    "toStudentId": 23,
    "fromQueueNumber": 8,
    "toQueueNumber": 5,
    "status": "Pending",
    "createdAt": "2026-11-15T16:30:00Z"
  },
  "expiresAt": "2026-11-15T16:30:45Z"
}
```

**3. Принятие или отклонение (`Клиент Б -> Сервер`):**
```json
{
  "type": "switch.accept",
  "requestId": 108
}
```
*(Для отклонения используется `"type": "switch.reject"`, для отмены инициатором — `"type": "switch.cancel"`.)*

**4. Результат обмена (`Сервер -> Клиент А и Клиент Б`):**
```json
{
  "type": "switch.resolved",
  "request": {
    "id": 108,
    "queueId": 42,
    "fromStudentId": 15,
    "toStudentId": 23,
    "fromQueueNumber": 8,
    "toQueueNumber": 5,
    "status": "Accepted",
    "createdAt": "2026-11-15T16:30:00Z"
  }
}
```
После отправки `switch.resolved` со статусом `Accepted` сервер атомарно меняет студентов местами в БД и транслирует `queue.updated` в SSE-поток `/queues/42/stream`.
